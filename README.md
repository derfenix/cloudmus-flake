# cloudmus-flake

Nix-обёртка над [CloudMus](https://github.com/cloudmus/cloudmus): собирает плеер из
исходников на x86_64-linux. Не форк — в коде CloudMus ничего не меняется.

## Что нужно

Nix с включёнными flakes:

```nix
experimental-features = nix-command flakes
```

Больше ничего. Qt, libmpv, TagLib и Python-пакеты берутся из nixpkgs, исходники — архив
с GitHub по хешу, так что сборка идёт без сети.

## Сборка и запуск

```sh
nix build        # результат в ./result
./result/bin/cloudmus
nix run          # то же самое, через meta.mainProgram
```

`bin/cloudmus` — лаунчер на несколько строк: он раскладывает манифесты бэкендов и
запускает `bin/cloudmus-qt` (его оборачивает `wrapQtAppsHook`, чтобы находились плагины
Qt). Манифесты нужны потому, что фронт ищет установленные бэкенды только в
`$XDG_CONFIG_HOME/cloudmus/backends.d` — так же делает AppRun в их AppImage.

## Что получается

Три источника, как в AppImage: локальная папка, Yandex Music, YouTube Music. Каждый —
отдельный процесс, который фронт поднимает по манифесту.

Пинов два, оба осознанные:

* CloudMus 0.6.4 — тег их релиза. Обновляется автоматически, см. ниже.
* библиотека `yandex-music` 3.2.2 — её нет в nixpkgs, собираем из sdist сами. Версия та
  же, что в их AppImage; список зависимостей взят из метаданных самого релиза. Пин
  двигается руками: между версиями у библиотеки меняются зависимости и extras, и
  автоматизировать это рискованно.

## Как убедиться, что сборка живая

Тесты включены и идут внутри сборки, в песочнице без сети: у библиотеки `yandex-music`
2367 проходит, 59 пропускается (пропуски — её же проверки на extras, которые мы не
ставим), у бэкенда Yandex Music 84. Поэтому `nix build` сам по себе уже проверка.

Отдельно можно посмотреть, что бэкенды действительно поднимаются:

```sh
./smoke-test.sh
```

Скрипт запускает собранное приложение с отдельным `HOME`, `QT_QPA_PLATFORM=offscreen` и
`dbus-run-session`, ждёт все три бэкенда, печатает их и содержимое манифестов, а потом
гасит только свои процессы — по точному PID.

## Чего здесь нет

* Sentry и Google Analytics выключены. Сборка без DSN, и в домашнем пакете телеметрия не
  нужна; в AppImage DSN зашит, поэтому поведение отличается.
* Строки самого Qt — кнопки стандартных диалогов, файловый диалог, контекстные меню —
  остаются английскими. Их CMake склеивает путь к каталогам как `${prefix}/${абсолютный
  путь}`, которого не существует. Отчёт: [issue #8](https://github.com/cloudmus/cloudmus/issues/8).
* Жёсткое убийство приложения (`kill`) оставляет процесс `cloudmus_backend_yandex`:
  обработчика SIGTERM в приложении нет, и штатное завершение не выполняется. Отчёт:
  [issue #9](https://github.com/cloudmus/cloudmus/issues/9).

## Обновления

`.github/workflows/update.yml` раз в неделю и по кнопке смотрит последний релиз
`cloudmus/cloudmus`. Если он новее пина, хеш считается по реально скачанному архиву,
сборка flake проверяется, и только после успешной сборки идёт коммит. Пин
`yandex-music` не трогается. Логику можно прогнать и руками: `./scripts/update-cloudmus.sh`.
